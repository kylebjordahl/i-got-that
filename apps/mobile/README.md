# caretaker_app (Flutter — iOS + Android + web)

Plain Flutter project (intentionally **not** Nx-managed; driven by the `flutter`
CLI). The Flutter SDK is required and is not installed by the backend toolchain.

## First-time setup

The platform runner directories (`ios/`, `android/`, `web/`) are committed, but
their ephemeral parts (generated plugin registrants, the Gradle wrapper,
`local.properties`, CocoaPods output) are git-ignored. After installing Flutter:

```bash
cd apps/mobile
flutter create . --platforms=ios,android,web --project-name caretaker_app
flutter pub get
```

This fills those in without overwriting `lib/main.dart`, `pubspec.yaml`, or the
committed per-flavor build config.

## Flavors

Two flavors, `staging` and `prod`, matching the two app identities so both can
be installed side by side:

| Flavor    | iOS bundle id                   | Android applicationId           | Name          |
| --------- | ------------------------------- | ------------------------------- | ------------- |
| `staging` | `com.kylebjordahl.igt.staging`  | `com.kylebjordahl.igt.staging`  | `IGT Staging` |
| `prod`    | `com.kylebjordahl.igt`          | `com.kylebjordahl.igt`          | `IGT`         |

iOS reads its per-flavor config from `ios/Flutter/{staging,prod}*.xcconfig`
(generated by `flutter_flavorizr`); Android's lives in the `productFlavors`
block of `android/app/build.gradle.kts`, which is hand-written — the
`flavorizr:` block in `pubspec.yaml` is iOS-only.

## Run

```bash
flutter run -d chrome                         # web
flutter run -d ios     --flavor staging       # iOS simulator
flutter run -d emulator-5554 --flavor staging # Android emulator
```

Against a local `wrangler dev` backend, point the app at the host machine —
`localhost` inside an Android emulator is the emulator itself:

```bash
flutter run --flavor staging --dart-define=API_BASE_URL=http://10.0.2.2:8787
```

Cleartext HTTP to those loopback hosts is permitted in **debug builds only**
(`android/app/src/debug/`); release builds stay HTTPS-only.

## Build

```bash
flutter build web
flutter build ios --no-codesign
flutter build apk --debug --flavor staging   # fast Android sanity check
flutter build appbundle --flavor prod        # what ships to Play
```

## Test / analyze

```bash
dart format lib test    # CI runs this with --set-exit-if-changed
flutter analyze
flutter test
```

Note that `defaultTargetPlatform` is `TargetPlatform.android` under
`flutter test`, so widget tests get the Android branch of any platform check by
default; use `variant: TargetPlatformVariant.only(TargetPlatform.iOS)` to
exercise the other side (see `test/widget_test.dart`).

## Platform differences

Three things are iOS-only today, and the UI hides rather than fails on Android:

- **Push notifications** — the `igt/push` MethodChannel is implemented only in
  `ios/Runner/AppDelegate.swift`, and the server sender is APNs-only. The whole
  notifications section is hidden off iOS.
- **Sign in with Apple** — works on iOS (OS sheet) and web (redirect flow).
  Android would need an Apple Services ID and an `intent://` server callback,
  so the button is hidden there; Google and magic link both work.
- **Location geocoding** — MapKit, so the location picker degrades to plain
  text elsewhere. Without coordinates there is no travel-time seed, so events
  created on Android fall back to the family's drop-off/pickup window.

## API client

The typed Dart API client is generated from the backend's OpenAPI spec into
`lib/api/generated/` (see `/tools`). It is git-ignored and regenerated.
